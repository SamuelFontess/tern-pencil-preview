# AGENTS.md

Tern plugin (Luau + a Node program) that opens pen.dev `.pen` designs as a native editor, with a read-only
whiteboard mirror kept as a separate, explicit command. Read the spec before changing editor behavior:
`docs/superpowers/specs/2026-10-17-native-editor-design.md`; the task list is
`docs/superpowers/plans/2026-10-17-native-editor.md`. Both are local working notes, ignored by git and not
published.

## Gate

```
python scripts/gate.py [--engine]
```

Type-checks every non-test `.luau` with `luau-lsp analyze --definitions=tern.d.luau` (any diagnostic fails, lint
included), checks with `luau-ast` that `window.luau`'s `EDITOR_LOADERS` preloads every module the editor requires,
each after the modules it requires itself (a `require` it cannot follow, such as a computed path or `pcall(require, ...)`, fails too), runs
`luau tests/run.luau`, the Node unit tests (`npm test`) and the build check
(`npm run check:build`). `--engine` also runs the real-engine integration tests (`npm run test:engine`); set
`TERN_PENCIL_CLI` first and build the runtime bundles (`npm run build`). Luau tools: `$LUAU_TOOLS` (default
`D:/tools/luau`; `luau`, `luau-lsp` and `luau-ast`). `tern.d.luau` is generated by `tern plugin types .` and is not committed.

## Conventions

- Every `.luau` file starts with `--!strict`. Modules: `require("./lib/x")`, relative to the caller.
- Tabs for indentation, as in the Tern SDK examples.
- Pure logic lives in `lib/`; `window.luau` wires it to Tern, loading each heavy module chain one tick at a time
  (a window hook has a 50 ms budget; `board.luau` and the `editor_*.luau` modules are only required when their
  command or the `.pen` route first runs, never at window load). A module compiles when first required and a busy
  machine makes that slow, so keep modules to a few hundred lines, list every module the editor requires in
  `EDITOR_LOADERS` (window.luau) after the modules it requires itself (the gate checks both), and never `require`
  inside a tick that does work. The chain, and the second run of a tick Tern killed (with a toast telling the user to reload plugins), are
  `lib/editor_chain.luau`.
- A tick makes at most one slow native call (`tern.fs.write/mkdir/remove/list/read`, `tern.kv.set`, `tern.process.run`,
  `cx:toast`, `cx:pick`, `cx.whiteboard:*`): on a busy window any one of them can take most of the 50 ms,
  and Tern kills the hook without a Lua trace. Exception: a read whose answer decides a write to the same shape shares
  that write's tick (the label of a target: apart, what the user types in between would be overwritten).
  `tests/editor_board_test.luau` counts the calls per timer callback. `Core.tick` gives the status file its own tick
  (the "mark") before a tick that makes a slow call; `Core.quick` is for a tick that only checks and schedules.
- Reading `editor/projection-status.json` after a kill: `entering` is the tick that was last marked. A mark that Tern
  kills leaves the name of the tick it was marking (which never ran), and when two `tick` chains interleave (mark A, mark
  B, work A) it names B while A runs. A tick that finished has an entry in `by`; on a first run the dead one has none.
- Unit tests in `tests/*_test.luau`, registered in `tests/run.luau`; they install the `tern` stub from
  `tests/stub.luau` and never touch the real Tern API or network.
- Processes only through `tern.process.run` with a callback and `timeout_ms`; never block the host (2 s per
  call). The one exception is the editor's owner (`editor_start.luau`), which has no timeout: it runs until it is asked
  to end (`close_editor`) or no window asks for it, and it survives a plugin reload (only its callback is dropped; the
  window finds it again by its session record). The editor never opens, parks or closes a pane (`cx.layout:*`): one such
  call can take most of a window hook's 50 ms on a loaded machine. The Luau host never writes the user's `.pen`; the board mirror stays read-only.
- Tests assert behavior, not wording or wiring.
- The Node editor program (`editor/`, bundles in `runtime/`) may manage external processes (the Pen CLI) with
  asynchronous I/O. Only the editor's explicit Save operation publishes to the original `.pen`.

## Node Editor

- `npm test`: Node unit tests, no engine/Tern/network.
- `npm run test:engine`: real integration against the Pen CLI.
- `npm run build` / `npm run check:build`: bundle `editor/src/` to `runtime/editor.mjs` and `runtime/mcp.mjs`, or
  check the bundles are current.

## Commits

- `main` gets one commit per release or per user-facing change, squashed, never the work-in-progress history of a
  branch. Conventional type and a subject a reader understands without context (`fix: keep the board open when the
  plugin's timers stop`), and a body that says what changed for the user and why.
- Never put internal names in a message on `main`: task ids (`NE-30`), branch or worktree names, "review round",
  "merge: …" of task branches, checklist ticks. Work branches may commit freely; their history stays local.
